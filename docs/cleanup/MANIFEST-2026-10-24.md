## 0. The four answers (get-deeper) — these are the plan

**Field.** Data migration with an epistemics core. The practitioner is a **staff engineer doing a
post-incident documentation cleanup**: they classify, move and prove; they never summarise. The
standard is a tree a cold agent can act from, not a tree that reads well.

**1. What would that practitioner do that this brief does not ask for?**

They would not start by classifying files. They would build the **citation graph** first: for every
number in the tree, name (a) the command that produced it and (b) the artifact holding the output.
Then classify by *who reads it*, not by how good it reads.

The brief's KEEP/EXTRACT/ARCHIVE is a judgement about prose. The professional move is narrower and
mechanical: **a fact with no consumer is deleted, not archived** (`knowledge.md`), and **a fact whose
`verified-by` cannot run is not a fact** (`check.md`). That single test reclassifies several files
the brief would keep — `00-facts.md` mixes measured physics with claims whose instrument is gone.

**2. What is the rawest material?**

Not the research prose — the **instruments and their outputs**: `bench/gfx1100-probes/*.cpp` with
`results.json`, the hypothesis reports' raw logs on the host (`~/a1`, `~/a4`, `~/a9`, `~/b1`), the
GGUF bytes themselves, the publisher's `rco-allocation.txt`, and the engine source. The research
docs are digests of those; `HANDOFF.md` is a digest of the digests. Three layers of abstraction is
exactly how a number drifts — and it has, three times: 619 GB/s presented as the wall, `n = 1.57`
back-fitted from a measurement, 752 GB/s assumed for 69 % of the file.

**3. What methods and tools?**

| method | why it fits | source |
|---|---|---|
| the four-way split — **measured / decided / assumed / trap** | every failure here has been a category error, so the split *is* the migration | `knowledge.md` |
| `verified-by:` and `superseded-by:`, never editing a superseded fact | the record of what was believed is evidence | `knowledge.md` |
| class budgets, not line counts | 189 lines of AGENTS.md is the symptom, not the disease | `agents-md.md`, `knowledge.md` |
| the citation graph, computed | `grep -l <number>` over the tree; a fact cited nowhere is dead, a citation with no fact is a dangling pointer | this manifest, §3 |
| the negative control applied to *docs* | delete a fact's cited file; if nothing breaks, the citation was decorative | `check.md` |
| `git log --follow` per archived file | provenance line for the archive index, cheap | git |

**4. What outside the agent or the user shows the result is right?**

Three arbiters, in order of strength:

1. **The GGUF reconciles arithmetically** — metadata + Σ tensor bytes = file size, closes to 0 B.
   Any fact about the file must survive this.
2. **The publisher's `rco-allocation.txt` and the GSQ grid tables** — ground truth for the recipe and
   the grids, independent of anything this project wrote.
3. **A cold-start check**: a fresh agent given only the new tree must reproduce three named numbers
   using only the commands the tree gives it. If the tree cannot produce its own numbers, the clean
   failed, however tidy it looks.

Not an arbiter: my summary, a subagent's report, or the fact that the tree is smaller.
